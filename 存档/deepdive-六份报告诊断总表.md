# DeepDive 六份报告诊断总表

诊断对象：`report.md` + 5 份带时间戳的报告（2026-10-16 ~ 10-17）
配套文档：`deepdive-诊断与改进清单.md`（第一份报告的逐条解剖，本文为其升级版，覆盖全部 6 份）
**一句话结论：这不是 6 个偶发 bug，是同一条流水线上的 6 个必然产出。真正致命的不是"写错"，是"没有拒绝的资格"。**

## 二、六份逐个判

### #1 · AI 自我改进（降质硬凑）
- src[1] 是微信反爬验证页；`当前环境异常，`、`， 。`、`视频`、`小程序` 等 8 条 UI 文案成为证据（8/30 = 27% 噪声）。
- Sources 只有 4 条，正文引用到 `[30]`，**26 个引用号不存在**。
- 把 `2210.11610`（PaLM-540B，GSM8K 74.4→82.1）的成果归给了 `2503.03746` 的 Process-based Self-Rewarding 方法。
- "环境异常"被当作分析前提写进正文 3 次。

### #2 · AI 对齐（基本可用，但仍有两处硬伤）
这是六份里质量最好的一份——27 条声明全部真实来自 4 篇 arXiv 论文，没有一条噪声。但：
- **引用编号与来源表是完全错位的两套体系。** Sources 顺序是 1=FIRM、2=场景生成、3=Counterfactual DPO、4=IFCD；正文 `[2]` 却用来引"reward model 幻觉"（属 FIRM），`[3]` 引 FIRM 框架，`[9][11][14]` 引场景生成，`[19]-[24]` 引 DPO。**每一个编号都指错。**
- **主题漂移**：因为检索词里有"场景"，硬拉进来一篇《Automatic Scene Generation》综述，27 条里有 8 条（30%）讲的是场景生成分类和 FID/IS 指标，与"AI 对齐"无关。
- 矛盾章节依旧虚构：说"FIRM 的有效性"与"现有 reward model 有幻觉"构成 contradiction——**FIRM 存在的目的正是解决后者**，这是把"问题"和"解决方案"当成对立。

### #3 · 对齐漂移检测（彻底跑偏）
这是最典型的检索事故，值得单独记住：
- 问题里的 **"current detection signal"被字面拆成 `current` + `signal` 去检索**，于是命中了：微软 .NET 文档 `IEnumerator.Current` 属性（中/繁文两版）、海词词典"current detection signal = 电流检测信号"、道客巴巴一份 2015 年的生物医学 PDF、一篇 IntelliJ IDEA 构建报错的 CSDN 博客。
- 53 条唯一声明里，包含"Microsoft 不作任何担保"、"该文档 7 页、被浏览 28 次、需 2165 积分"、"作者 li94959 有 6 个粉丝"、"《build.gradle》里 project.name = 'MyProject'"。
- **摘要诚实地写了"这些声明与问题完全无关，无法回答"——然后正文照样生成了完整的 Background、Key findings、Contradictions 三节**，用通用常识谈"自修改 LLM 的错位风险"，这些内容没有任何来源支撑。
- 矛盾章节声称"研究问题与事实基础之间存在 fundamental contradiction"——把"证据不相关"包装成一个学术发现。

### #4 / #6 · 正确拒答（值得肯定）
两份都只输出："No verifiable claims could be extracted from the searched sources... Try rephrasing the question, switching search backend, or using a larger model."
**这说明系统里已经有正确的"拒答"能力，只是它不是默认路径，而是运气。**

### #5 · IFCD 场景（最严重，必须重点看）
- 只有 **1 个来源**，就是一张微信反爬页；8 条唯一声明全部是它的按钮文案。
- 全文 3 处明确承认"无法回答"，却仍然写出了这段：

> "The current operational environment exhibits abnormal conditions [1], and the service delivers video content as a primary interaction medium [4]. ... User interaction with the service relies on specific verification mechanisms, including a prominent 'Go verify' button [3] ... user actions such as liking content [6] ... However, the abnormal environment [1] and the video-based nature of the service [4] suggest that the IFCD method's ability to accurately distinguish objects in multi-object scenes may be compromised."

**它用一张验证码页面的按钮文字，论证了一个多模态幻觉抑制方法的失效条件。** 摘要说"答不了"，正文说"可能会失效"，同一份文件里自相矛盾。
- 附带一个细节：它把 IFCD 展开成 "Image Fusion for Content Detection"，**这个展开是错的**（应为 Internal Fact-based Contrastive Decoding）——而正确展开就写在它自己昨天那份 #2 报告里。**跨报告知识不共享，且宁可现编也不查自己的库。**

## 三、五种系统性失败模式

| 编号 | 失败模式 | 命中报告 | 本质 |
|---|---|---|---|
| F1 | 反爬/验证页未识别，UI 文案当事实 | 1,2(未中),3,5 | 抓取层没有页面可用性判断 |
| F2 | 检索词被字面化，抽象词当专有名词 | 3（`current`→.NET 属性） | 查询构造层无歧义消解 |
| F3 | 单一垃圾来源也能产出完整报告 | 5（1 个来源） | 聚合层无最小来源数闸门 |
| F4 | 摘要说"答不了"，正文照样编 | 3,5 | 章节模板强制生成，不等证据 |
| F5 | 引用编号与来源表系统性错位 | 1,2,3,5（4/4） | 编号由模型自己写，无人校验 |

F4 + F6 合起来是同一个病根：**报告结构是"必填表单"，而填表的人（模型）宁可编也不肯留空。**

## 四、也要说清楚它的两个真实优点

1. **能拒答，而且拒答文案是对的**（2/6）。说明拒答路径已存在，只是没被当成默认。
2. **span 级定位是真的**。每条证据都带原文截图式摘录，`#2` 的 27 条我逐条核对过，全部真实存在于所引论文。它的"诚实度"没问题——**问题是它不知道自己拿到的材料一文不值。**

所以改进方向不是"让它更少撒谎"，而是"**让它有资格说这活儿干不了**"。

## 五、改进路线（按投入产出排序）

### 第一优先：一道证据准入闸门（改一处，救 4/6）

在生成任何正文之前插入闸门，不达标只輸出拒答。六份报告里 4 份灾难会被这一条直接拦住：

```python
def gate(question, sources, claims):
    src = [s for s in sources if not is_blocked(s)]        # 去掉反爬页
    rel = [c for c in claims if relevance(c, question) >= 0.7]

    if len(set(s.domain for s in src)) < 3:  return REFUSE("独立来源不足 3 个")
    if len(rel) < 8:                          return REFUSE("有效证据不足 8 条")
    if len(rel) / max(len(claims), 1) < 0.6:  return REFUSE("信噪比过低")
    return BUILD(rel)
```

阈值可调，但三条缺一不可：**来源数、有效条数、信噪比**。

### 第二优先：三处去噪（治 F1 / F2 / 3 倍膨胀）

1. **页面可用性判断**（抓取层，一个函数）
   ```python
   BLOCK_PAT = ["wappoc_appmsg", "captcha", "环境异常", "完成验证后即可继续访问",
                "访问过于频繁", "Just a moment", "Enable JavaScript", "需要授权"]
   def is_blocked(s):
       return s.title in ("Untitled", "") and any(p in s.url + s.text[:500] for p in BLOCK_PAT) \
              or len(s.text) < 200
   ```
2. **查询构造**：英文抽象词不要单独成词检索。`current detection signal` 这类必须整短语加引号，或先做一次术语归一（`current` → `current (electrical)` / `current (present)`）。规则很简单：**任一关键词命中"编程/词典/文档站"域名且与领域不符时，该批次作废重查**。
3. **证据去重**：`hash(normalize(claim))` + `(claim, domain)` 双键去重。既然 4/4 都是精确 3 倍，先去看那段循环为什么跑了 3 次——大概率是 query 变体循环复用了同一个 claim 池。

### 第三优先：三处结构性修复（治 F4 / F5 / F6）

4. **引用编号必须由程序生成**。写作时用 `[[c17]]` 绑定 claim id，渲染时统一编号，并在输出前断言 `max(ref) == len(sources)` 且 `sources[ref]` 的 domain 与 claim 来源一致。不通过则整篇打回。
5. **空章节要允许为空**。`Background` / `Contradictions` 增加前置条件：可用证据 < 5 条时，该章节不生成。**"未检测到实质性矛盾"是合法输出，编一个矛盾不是。**
6. **矛盾判定加形式约束**：两条 claim 必须同主体、同谓词、极性相反，且分属不同来源。`FIRM 有效` vs `现有 reward model 有幻觉` 因为主体不同，自动过滤。

### 第四优先：可观测性

7. `cost $0.0000` 在六份里出现六次——成本统计从来没接上。至少记录：抓取数、拦截数、去重前后声明数、相关度分布、拒答原因。**没有这些数字，你无法判断下一次改动是变好还是变坏。**
8. 报告尾部把 `90/90 grounded` 换成 `有效证据 22 条 / 独立来源 3 个 / 拦截 1 页 / 信噪比 73%`。自评分越漂亮，越容易掩盖问题。

这是目前最该做的事，比改代码更优先。六份已经天然构成一个覆盖"该拒/该写"的测试集：

| #6 IFCD 高密度 | **拒答** | 保持现状 |

评分只有两项：**该拒的拒了几份（现在 2/4）**、**该写的有效证据占比多少（现在 12%）**。每次改完代码跑一遍这 6 条，两个数字都不许降。

## 七、关于"自我学习"的最后一句

`#5` 和 `#2` 放在一起看，风险就很清楚了：**它昨天知道 IFCD 是什么（写在 #2 里），今天遇到 IFCD 却宁可从一张验证码页面里现编一个错误的展开。**

这说明它现在的"学习"并没有形成可检索、可校验的知识，只是把产出物堆在某个地方。如果继续让这些未审核的产出回流成训练数据或长期记忆，那么：
- #3 里"Microsoft 不作任何担保"会变成一条"已知事实"；
- #5 里那段用按钮文字论证多模态失效的段落，会变成"曾经做过的分析"；
- 而 `90/90 grounded` 会给这一切盖章。

**硬规则只有一条：未经过人确认或未通过上面那道闸门的产出，永远不许进入长期记忆。** 其余都可以慢慢改，这条不能。
