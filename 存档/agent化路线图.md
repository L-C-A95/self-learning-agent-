# 从流水线到 agent：优化路线

对象：`deepdive_research 0.3.2` + 你的 4 个脚本 + 9 处补丁
状态：claim 级已可验证、能拒答、能离线查教材。**但还不是 agent。**

---

## 一、先把"自我学习"拆成四件事

这个词被用得太糊，拆开看，只有一层是你现在真正需要的。

| 层 | 是什么 | 能做到吗 | 现状 |
|---|---|---|---|
| 1 记忆 | 记住做过什么、结论是什么 | 能 | 有一半，但存的是散文 |
| 2 积累 | 新知识入库、可被复用 | 能 | 有，但没有准入标准 |
| **3 规则编译** | **同样的错不再犯** | **能，且最值钱** | **完全没有** |
| 4 权重更新 | 模型参数变强（SFT / RLHF） | 技术上能，但**现在不该做** | 无 |

**你要的是第 3 层，不是第 4 层。**

第 3 层的实现方式不是训练，是：**失败 → 提炼成规则 → 下次执行前加载规则**。

而第 4 层现在做等于自伤：你的错误类型还在不断增加（3 倍重复 → 反爬页 → 主语篡改 → 摘要归因错误 → TPO 缩写脑补，五轮下来每次都是一个新类型）。**错误类型还没收敛的时候去训练，等于把这些错误固化成权重。**

## 二、它现在不是 agent，是流水线

| 环节 | 一个 agent 该有 | 它现在有 |
|---|---|---|
| 目标 | 明确成功判据 | 只有一个 topic 字符串 |
| 计划 | 拆步骤、定预算 | 无 |
| 行动 | 检索 / 抓取 / 抽取 / 写 | 有 |
| 观察 | 记录证据、页码、失败 | 有 |
| **判定** | **对照判据判 pass/fail** | **无**（qc_gate 只查格式和关键词） |
| **修复** | **不达标就换查询/换源/重做** | **无**（不达标就丢弃） |
| 终止 | 预算用尽仍未达标 → 明确失败 | 无预算概念 |

差的不是记忆，不是模型，是**「判定」和「修复」这两步，以及一个「预算」**。

最小可用的 agent 循环就是这段：

```python
task = {
    "question": q,
    "must": ["≥3 个独立来源", "每条结论有出处", "无来源支持的结论必须删除"],
    "budget": {"max_searches": 9, "max_minutes": 10},
}

for attempt in range(3):
    result = run(task)
    verdict = verify(result)                 # 独立程序，不是同一个模型自评
    if verdict.ok:
        return result
    task = repair(task, attempt, verdict.reasons)   # 换查询词 / 换来源 / 缩小问题
else:
    return REFUSE(verdict.reasons)           # 明确失败，带原因，不硬凑
```

**这三十行就是 agent 与 pipeline 的分界。** 不是加记忆，不是换模型。

## 三、三阶段路线

### 阶段一：让产物可信（1–2 周，每项独立验收）

| # | 做什么 | 治什么 | 验收 |
|---|---|---|---|
| 1 | **句子级合成校验**：正文每句必须带 ≥1 个 `[n]`，且该 claim 与这句实体重叠达标，否则删句 | TPO 缩写脑补、跨来源归因、"机制尚不清楚"补白 | 拿 033526 那份报告跑，含 "Truthful and Precise Output" 的句子被删 |
| 2 | **数字一致性**：报告中每个数字必须在证据里出现过 | 25%、-6.23、12%、50% 这类精确数字来源不明 | 造 3 个假数字，全部被抓 |
| 3 | **来源分级 T0–T3**：T0 论文/官方、T1 机构媒体、T2 门户转载、T3 UGC；要求 ≥1 个 T0 或 ≥2 个 T1 | 6 个源全是门户转载 | 报告头部输出等级分布 |
| 4 | 语言护栏：正文语言与提问语言一致 | Background 中文、Key findings 英文 | 中英混杂段落归零 |

**第 1 项优先级最高**，因为它同时是阶段二的 verifier 基础——写一次，用两处。

### 阶段二：变成有任务的 agent（2–4 周）

| # | 做什么 | 要点 |
|---|---|---|
| 5 | **task spec** | 每个任务写清成功判据，不允许"写一份关于 X 的报告"这种无判据任务 |
| 6 | **verifier 独立成进程** | 不能用同一个 7B 自评（它会给自己打 100 分）。规则+程序为主，模型只做兜底 |
| 7 | **repair 策略** | 三种动作：换查询词、放宽/收紧来源域、把问题拆小。三次失败就拒答 |
| 8 | **budget** | 搜索次数、抓取页数、耗时上限。没有预算的 agent 会无限重试 |
| 9 | **明确失败** | `REFUSE(reasons)` 是一等公民，不是异常分支 |

验收标准：**同一批 6 个问题跑两遍，判定结果必须一致**（现在 2/6 和 4/6 之间摇摆，这就是没有稳定判定的表现）。

### 阶段三：正确的记忆（边用边建，1 个月）

| 层 | 存什么 | 准入 | 用途 |
|---|---|---|---|
| **事实层** | claim + 来源 + 页码 | 必须过 verifier 与 support 校验 | 回答问题时召回 |
| **规则层** | 从失败提炼的"不要做 X"（人可编辑的纯文本） | 人来确认，一次一条 | 每次执行前注入 prompt |
| **任务层** | 问过什么、结论是什么、哪些被否决过 | 自动记录 | 避免重复问（治 08:54 / 09:26 那次原地转圈） |

三条硬规则：
1. **只有通过 verifier 的产出才准进事实层**，其余进临时层、7 天过期
2. **规则层必须是人可读的短句**，不是向量，不是散文
3. **定期降权**：长期未被召回的记忆降权，防止垃圾沉淀

`vector_kb.py` 现在还停在"把报告正文切段进库"，那存的是格式噪音（Evidence、Sources、元信息）。改造方向就是上面这张表。

## 四、关于微调：什么时候才轮得到它

**三个条件必须同时满足，缺一不做：**

1. 有 **500 条以上**人工确认过的 `(问题, 证据, 合格答案)` 三元素
2. 有稳定的自动评测集（现在这 7 份报告 + 2 份新报告就是雏形，但需要冻结成 20–50 题）
3. 错误类型已经收敛——连续 5 次改动不再出现**新类型**的错误

满足之后也不是 RLHF，而是 **LoRA SFT**，只教两件事：引用格式、以及**该拒答时拒答**。这两件事最确定、最便宜、最不会反噬。

**现在做微调的典型后果**：模型学会了"用 [n] 格式引用"，同时也学会了"7B 那套脑补风格"，然后你把补丁建立的防线从权重层面绕过去了——比现在更难查。

## 五、7B 的正确定位：给它更少的自由

这是最反直觉、但最重要的一条。

| 任务 | 7B 胜任吗 | 该谁做 |
|---|---|---|
| 从段落里抄一句原文 | 能 | 7B |
| 把 claim 和 excerpt 比对 | 不能（会"觉得差不多"） | 程序（专有名词+数字，已实现） |
| 判断来源可不可信 | 不能 | 域名分级表 |
| 综合成段 | 能写，但会补白 | 7B 写 + 每句强制引用 |
| 判断自己写得对不对 | 不能（自评 100%） | verifier |
| 决定下一步搜什么 | 勉强 | 规则 + 有限枚举 |

**结论：不要在 7B 上加更多自由（比如让它自己规划、自己选题、自己判分）。把判断全部外移到程序和规则，只让它做「抽取」和「按给定结构改写」。**

小模型 + 强外部检查，比大模型 + 自觉，在你这个场景里更可靠。

## 六、如果只做一件

**做阶段一的第 1 项：句子级合成校验。**

理由：它是唯一一个同时满足三个条件的改动——
- 一次解决三类现存错误（缩写脑补、跨来源归因、无依据补白）
- 直接变成阶段二的 verifier 第一条规则（写一次用两处）
- 用现有的 `support.py::entities()` 就能实现，约 80 行

做完这一项，你手上就同时有了"可信的报告"和"agent 的判定器雏形"。**这是流水线和 agent 之间那块最窄的桥。**

---

## 七、一句话总结

你现在缺的不是让它学，是让它**知道自己什么时候没做成**。

一个会说"这次没达标，原因是一、二、三"的系统，比一个会背书的系统更接近智能；而前者只需要 verifier 和预算，不需要训练。
