# DeepDive 报告诊断与改进清单

诊断对象：`E:\AI_Workspace\report.md`（DeepDive 生成，2026-10-16，自称 `90/90 grounded`、cost $0.0000）
诊断结论：**这是一份"流程跑通、质量失控"的样张。管道每个环节都执行了，但没有一个环节有权拒绝脏数据。**

---

## 一、事故回放（一句话版）

爬虫抓微信公众号文章时被反爬拦截，拿到了"当前环境异常，完成验证后即可继续访问"的验证页。
系统没有识别这是拦截页，照常切句 → 把 `当前环境异常，`、`， 。`、`视频`、`小程序` 当成"事实声明" → 用"原文子串匹配"校验 → 全部通过 → 打上 `90/90 grounded` 满分 → 最后**"当前环境异常"这个反爬提示，被当成分析前提写进正文 3 次**。

---

## 二、必须修的 P0 缺陷

### P0-1　没有"页面可用性闸门"
**现象**：src[1] 是一个 `mp/wappoc_appmsgcaptcha` 的验证页，仍被登记为有效来源（标题 `Untitled`）。
**根因**：抓取后只判断 HTTP 200 + 正文长度，没判断"这是不是内容页"。
**修法**：
- URL/HTML 特征黑名单：`captcha`、`wappoc_appmsg`、`环境异常`、`完成验证后即可继续访问`、`Just a moment`、`Enable JavaScript`、`访问过于频繁`。
- 正文长度 < 200 字 或 有效段落 < 3 → 直接丢弃，并在日志里记 `BLOCKED` 而不是 `OK`。
- 标题为 `Untitled` 且 URL 含 query 参数 > 5 个 → 强制人工复核。

### P0-2　"grounded" 只校验子串，不校验语义
**现象**：`The system uses commas and periods.` ← 原文 `， 。`；`Video functionality is available.` ← 原文 `视频`。两句话确实"逐字出现在原文里"，但**没有任何信息量**，属于噪声被包装成证据。
**根因**：span grounding 是 `claim in page_text` 的字符串匹配，不是"页面支持该结论"。
**修法**：加第二道闸门 `relevance + informativeness`：
- 单条 claim 至少 8 个实词 + 含主语和谓语；纯标点、纯导航词、纯功能名词（`视频`/`小程序`/`赞`）直接过滤。
- 用一个小模型做三分类：`支持 / 部分支持 / 无关`，只保留前两类，并把分数写进报告。
- 对中文来源额外做"UI 文案指纹"过滤（点赞、在看、分享、阅读原文、轻点两下）。

### P0-3　证据去重完全缺失
**现象**：Evidence 编号 1–30 完整重复了 3 遍（31–60、61–90 内容逐字相同）。真实唯一 claim 只有 30 条，却报 90/90。
**修法**：`hash(normalize(claim_text))` 去重；同一 `(claim, source_url)` 只保留一条；报告顶部同时给出 `unique_claims` 和 `raw_claims` 两个数。**覆盖率分母必须是去重后的数**，否则指标本身就是假的。

### P0-4　引用编号与来源表脱节（最严重）
**现象**：正文引用了 `[1]`–`[30]`，但 Sources 表只有 4 条。`[5]`–`[30]` 共 26 个引用号**根本不存在**。
**为什么最严重**：读者无法核查任何一条，报告整体失去可信度；这比"结论错"更致命，因为它是系统性的、每一份报告都会发生的。
**修法**：
- 生成阶段用引用占位符（如 `[[c17]]`）绑定 claim id，最后统一渲染为编号，禁止模型自己写数字。
- 渲染后跑一致性检查：`max(ref_id) == len(sources)`，不等则**整篇打回**，不输出。
- 每条引用必须能解析到 `source_url + char_offset`，点开就跳到原文那句话（DeepDive 已有 offset，别浪费）。

### P0-5　多篇论文的结论被混成一篇
**现象**：摘要说"用 *this method*（Process-based Self-Rewarding）微调 540B 模型，GSM8K 74.4→82.1"。但这组数字出自 `2210.11610`（PaLM-540B），而 Process-based Self-Rewarding（`2503.03746`）实验用的是 Llama-3 / Qwen-2.5，**根本没有 540B**。
**根因**：写作阶段把三篇论文的"亮点句"拼成一段综述，丢掉了"哪句话属于哪篇"的绑定。
**修法**：所有数字类断言必须带 `source_id`，并且写作 prompt 里强制："一个段落引用多个来源时，每个数字后立即标注来源编号，不得把 A 结论的主语换成 B 方法。"

### P0-6　"矛盾章节"是模板强行生成出来的
**现象**：`Contradictions & open questions` 把"旧方法在数学推理上效果差"和"新方法在同一批 benchmark 上提升明显"对立起来，说这是 "fundamental tension"。**这不是矛盾**——论文原话就是"旧范式不行、我的新范式行"，两者恰好互相印证。整节为凑格式而虚构了一个学术争议。
**修法**：矛盾章节改为**可选**。触发条件：两条 claim 的 `source_id` 不同、主体相同、谓词相同、极性相反，且都能定位到原文。找不到就输出"未检测到实质性矛盾"，宁可空着也不许编。

### P0-7　章节标题重复
**现象**：`## Key findings` 出现两次（13/15 行），`## Contradictions` 出现两次（23/25 行）。
**修法**：模板渲染后做结构校验——标题集合去重、空章节删除、字数 < 50 的章节合并。

### P0-8　指标自嗨
**现象**：`cost $0.0000 USD`、`90/90 grounded`。前者说明成本统计没接上（或真没调付费 API），后者已被 P0-3 证伪。
**修法**：指标只保留可被外部验证的三项：`unique_claims`、`distinct_sources`、`human_spotcheck_pass_rate`（抽 5 条人工核对）。去掉"100%"这类自评。

## 三、建议增加的 P1 质量闸门

1. **来源多样性下限**：一份"研究进展"类报告至少 6 个独立来源、≥2 个域名；少于 3 个时报告顶部必须打灰标"低置信度"。
2. **时效校验**：抓取时记录 `published_at`，超过 12 个月的在正文里标 `(2022)` 这类年份；标题写"最新"就必须有近 3 个月的来源，否则改名。
3. **语言一致性**：中文标题的产物，正文应由中文模型重写一遍，不要让中文标题挂英文正文。
4. **双模型交叉审核**：报告定稿前，换一个模型以"审稿人"身份打分（引用完整性 / 结论与证据一致性 / 是否存在未标注推断），低于阈值退回重写。
5. **Top-N 抽样人审**：每次输出随机抽 3 条 evidence 给人看，人点"通过/不通过"，这个信号才是唯一可靠的回归基线。
6. **失败要报错，不要降级**：来源全部被拦时，正确行为是输出"本次检索失败，未获取到可用来源"，而不是硬凑出一篇。

## 四、关于"自我学习"的安全边界（最重要的一条）

现在的报告已经证明：**它会把反爬提示当真理，并且写进正文 3 次。**

如果这个系统会把自己的产出回灌成训练数据 / 经验库 / 长期记忆，那么：
- 脏证据 → 脏 claim → 脏记忆 → 下次检索时被当成"已知事实"优先召回；
- 错误会被复述、被强化，形成**自我确认闭环**（model collapse 的典型路径）；
- 而 `90/90 grounded` 这种自评分会不断给闭环背书，让它越错越自信。

**硬规则**：
1. **只有人确认过的 claim 才允许进入长期记忆**，未确认的放在临时层、定期过期。
2. 学习层与推理层隔离：回灌前必须过 `sources 完备 + 引用可解析 + 无噪声串` 三项检查。
3. 每次自学习留下 diff（学到了什么、来自哪条证据），可回滚。
4. 定期做"遗忘"：长期未被引用的记忆降权，避免垃圾沉淀。

## 五、这份能力实际能用来做什么

**现在就能用（风险可控）**
- 英文 arXiv / 公开网页的单篇精读与结构化摘要（抓取成功率高的源）。
- 建"claim–证据"对照库，人来判断，AI 只做搬运和定位。
- 内部技术雷达：每周扫一遍，人工筛 10%，输出"值得看"清单。
- 把你自己的长文档切句、抽结论、查内部一致性。

**暂时别用（风险高）**
- 对外发布的综述、行业报告、公众号文章。
- 任何需要给数字下结论的场景（投资、医疗、政策、技术选型）。
- 以微信公众号为主要信息源的选题（当前 100% 会踩反爬陷阱）。
- 让它"自主选题自主发布"——现在它连自己拿到的是一张验证码页面都不知道。

## 六、给本地 AI 的一段"自检 prompt"（可直接粘贴）

```
你刚生成的报告中，请逐项自查并如实回答：
1. 我的 Sources 表条数是否等于正文出现的最大引用编号？不等则列出缺失编号。
2. 是否存在"原文是页面 UI 文案"的证据（如 视频 / 小程序 / 点赞 / 环境异常 / 验证）？列出全部。
3. Evidence 列表是否有重复条目？重复率多少？唯一 claim 数是多少？
4. 每个含数字的结论，其来源是否与数字所在论文一致（核对方法名与实验模型规模）？
5. "矛盾/争议"章节中的每一条对立，是否两个来源都在结论层面真实对立？若否，删除该条。
6. 我的报告里有没有一句话，是我从常识推断、但没有任何来源支持的？标注出来。
以上任一项不通过，请先修正再输出，不要用"已充分验证"之类的措辞。
```
